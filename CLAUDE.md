# Daily — notes for Claude

- SwiftUI + SwiftData iOS app, iOS 17+, Swift 5 language mode. No server.
- Xcode project uses a file-system synchronized group: any file added under `Daily/` is in the target automatically. Don't add per-file entries to `project.pbxproj`.
- Colors come only from `Palette` in `Daily/Theme/Theme.swift` (each has a light and dark value). Don't hardcode colors in views.
- The user's schedule is read through `MySchedule` (`Daily/Schedule/Schedule.swift`), backed by UserDefaults keys in `Pref` and edited in `SettingsView`. Bump `Pref.revision` after settings change. Shuttle 7:45 AM out, 4:00 PM home. Gym days: leave work 3:00 PM, gym, Caltrain home from Sunnyvale.
- This environment can't build iOS. The user builds in Xcode and pastes errors back; keep changes small and conservative.
- Targets: `Daily` (iOS app, folders `Daily/`, `SharedCore/`, `Shared/`), `DailyMac` (macOS 14 app, same three folders, scheme `DailyMac`, entitlements `Config/DailyMac.entitlements`, sandboxed, same bundle id and iCloud container), `DailyWidgets` (widgets + Live Activity, folders `DailyWidgets/`, `SharedCore/`, `Shared/`), `DailyShare` (share extension, folders `DailyShare/`, `SharedCore/`). `SharedCore` must stay free of WidgetKit/ActivityKit. Extension Info.plists and entitlements live in `Config/` (not a synced folder).
- App, widgets and share extension talk through the App Group `group.com.kgeee.daily` (`SharedStore`). The app pushes a snapshot for widgets via `WidgetSync`.
- AI calls go through `AIClient` (Anthropic API, user's key in Keychain). Live trains use 511.org (`Caltrain511`).
- Unit tests live in `DailyTests/` (target `DailyTests`, host app `Daily`, shared scheme `Daily`). Add a test with any logic change; keep logic out of views where possible so it can be tested.
- Kinds of day are data, not a fixed enum: `DayType` (struct, `rawValue` id) looks itself up in `DayTypes` (`pref.dayTypes`, falls back to the original four built-ins). First-run setup (`SetupView`, logic in `Setup`/`SetupAnswers` in `Daily/Schedule/Onboarding.swift`) builds day types, routines, timetables and the week from the commute modes picked (drive, shuttle, train, bus, bike/walk, remote, plus gym and an after-work spot). Week pattern = Mon…Fri[,Sat,Sun]; "off" means a day off (also valid as a `DayTypeOverride`).
- Commute timelines come from `Routines` (`Daily/Schedule/Routines.swift`): per-DayType lists of `RoutineStep`, resolved by `RoutineResolver` with `Timetables` and one-day `StepOverride`s. Default routines are built from the old `Pref` values. Built-in step ids ("out", "work", "go", "gym", "home") are relied on by check-offs and tests.
- Signing team is `7CK43PG7GZ` (set in the project generator for every target).
- "Now" (current block, time left, next) is computed by `NowPlan` (`SharedCore/NowPlan.swift`) from `SharedStore.Item`s. Used by `NowCard` on Today, the `Now` widget, and the `NowAttributes` Live Activity (`Shared/NowActivity.swift`, synced by `NowActivity.sync()` after every `WidgetSync.update`). The Lock Screen toggle is `SharedStore.nowActivityEnabled`.
- Pomodoro: rules in `Pomodoro` (`SharedCore/Pomodoro.swift`); the running timer is `SharedStore.activeFocus` (App Group) so the Lock Screen card shows it; settings keys `pomo.*` live in the App Group defaults. `FocusController` starts/pauses/stops and logs `FocusSession`s; `FocusView` is the Focus tab. A running timer takes over the Now Live Activity (item id `NowActivity.focusItemID`).
- Month planning: `MonthView` (Today header → calendar icon), grid logic in `MonthGrid`. Events repeat none/daily/weekdays/weekly/biweekly/monthly (`EventRepeat`).
- UI kit in `Daily/Theme/DetailComponents.swift`: `DetailSheetLayout` + `DetailHero` (colored header with icon capsule, title, check circle) + `DetailCard`/`DetailRowLabel`/`DetailExpandableRow`/`DetailNotesCard`/`DetailDeleteButton`/`DetailPrimaryButton`, plus `PillSegment` (use instead of segmented `Picker`) and `ChoiceChip`. Hero colors are `Palette.hero*` / `BlockCategory.hero`. Detail sheets: `EventEditor`, `BlockDetailSheet` (any timeline block; `StepDayEditor` wraps it), `LogMealSheet`.
- Restaurants (Food → Restaurants): `Restaurant` model (Beli-style: `feelingRaw` loved/fine/disliked + `rank` within that group; score from position via `RestaurantRanking`, binary-insertion comparisons in `RankRestaurantSheet`). Visits are `FoodEntry`s with `restaurantID`. Search is Apple Maps (`PlaceSearch.appleMaps`, no key); Yelp ratings only if the user adds a Yelp key (Keychain account `yelpKey`, paid API). No location permission is used: searches center on saved places or the Bay Area.
- Maps & ratings: `MapsApp` (open places in Apple or Google Maps, `pref.mapsApp`; search with Apple or Google, `pref.placeSearch`). Google search = Places API (New) `searchText` with the user's key (Keychain `googlePlacesKey`); results carry `PlaceResult.google` ratings. No location permission.
- Photo journal: `JournalEntry` (photo as external storage, mood, caption) + meal photos (`FoodEntry.photo`), merged by `JournalItem.days`. `CheckInCard` on Today (window from `CheckIn.shouldPrompt`), `JournalView` (Today header book icon), `CheckInSheet`. Daily reminder `CheckIn.updateReminder()` (repeating notification, id `checkin.midday`). Photos are shrunk with `ImageTools.jpeg` (1600px). Camera needs `NSCameraUsageDescription` (set in the project generator).
- Voice planning: Today's mic button → `VoicePlanSheet` (`SpeechRecognizer` in `Daily/Services/Speech.swift`, needs mic + speech usage strings from the generator). `VoicePlanner` builds the prompt (with that day's timeline) and turns the AI reply into `EventDraft`s, which become `CustomEvent`s.
- Gym coach: `Coach.target` (progressive overload: +5 lb / +2.5 under 50 lb once all sets hit 10; else +1 rep; below 8 hold), `Burn` (MET × 3.5 × kg / 200 per minute; strength MET 5; `pref.bodyWeight`, fallback 170 lb), `GymWeek`. Sessions store `caloriesBurned` on finish and `cardioKindRaw`. AI coach chat `CoachSheet`/`CoachAI` can return a workout to start. Rest timer length `pref.restSeconds`.
- Habits: `DayScore` (`Daily/Models/DayScore.swift`) turns `ScoreInputs` into three rings (Move = water + workout if planned/done; Fuel = main meals + protein; Day = timeline check-offs (minus wake/wind/lunch/dinner) + check-in if expected). An empty ring counts as full. `Streaks.daily` forgives misses with freezes (earned per week at ≥ target days, max 2); `Streaks.weekly` for gym weeks (`pref.gymPerWeek`, default 3). `ScoreBuilder` (`Daily/Services/ScoreBuilder.swift`) builds scores/streaks/`WeekRecap` from SwiftData arrays. Views in `Daily/Views/Habits/`: `DayScoreCard` on Today, `ScoreDetailSheet`, `StreaksView`, `DayClosedOverlay` (once per day, UserDefaults `celebrated.<dayKey>`), `RecapView` (Sunday banner on Today; goal saved as text in `pref.weekGoal`). The older `WeekReviewView` is still reachable from Food.
- Meal estimates (`LogMealSheet` → `RecipeAI.estimate(meal:photo:place:)`): if the meal has a photo, a 1024px copy (`ImageTools.forAI`) goes to the AI as an image block (`AIClient.structured(images:)`, `AIClient.messageContent`) and the prompt (`RecipeAI.mealPrompt`) uses it for portion size; the picked restaurant is passed as context. Adding a photo to a meal with no calories estimates right away; with no name typed, the AI also suggests one.
- Invite import (Partiful, Luma, Eventbrite…): `EventImporter` / `EventPageParser` / `EventImportAI` in `Daily/Services/EventImport.swift`. Fetches the page on the phone and reads, in order: schema.org JSON-LD Event → event-like objects in embedded JSON (`__NEXT_DATA__`, preferring the one matching og:title) → AI on the page text (needs the Anthropic key). Entry points: share sheet (pending imports whose link `isEventLink` open `ImportEventSheet` instead of the recipe importer) and the "Got an invite?" paste card on a new `EventEditor`. `CustomEvent.link`/`location` (defaults ""); re-importing the same invite (matched by `EventImporter.canonical`) updates the existing event.
- iCloud sync: the app's `ModelContainer` comes from `DataStore.shared` (`Daily/Services/DataStore.swift`): CloudKit private database `iCloud.com.kgeee.daily` when `pref.iCloudSync` is on (default) and the user is signed in to iCloud, else the same store file local-only (`DataStore.mode` says which; shown in Settings → iCloud). CloudKit rules apply to every `@Model`: every stored property has a default or is optional, relationships are optional (`WorkoutSession.sets` is `[SetLog]?`; read `allSets`), no `@Attribute(.unique)`. "One per day" rows (`DayTypeOverride`, `BlockCheck`, `MealPlan`) are cleaned by `Dedupe.run` on each activation. Entitlements in `Config/Daily.entitlements`. TestFlight/App Store builds use the CloudKit Production environment: deploy the schema in CloudKit Console after adding fields.
- Mac app: entry `DailyMacApp` in `Daily/Mac/DailyMacApp.swift` (`#if os(macOS)`; the iOS `@main DailyApp` is `#if os(iOS)`). `MacRootView` = sidebar (`MacSection`, ⌘1–⌘7, ⌘N new event) showing the shared screens; `MenuBarLabel`/`MenuBarPanel` (`Daily/Mac/MenuBar.swift`) show what's on now from `WidgetSync.timelineItems` (title text from `NowPlan.menuBarTitle`). Background work shared by both apps lives in the `AppLifecycle` view modifier (`Daily/App/DailyApp.swift`). Platform differences go through `Daily/Theme/Platform.swift` (`inlineNavigationTitle()`, `platformKeyboard(_:)`, `noAutocapitalization()`, `wheelDatePickerStyle()`, `pagedTabViewStyle()`, `fullScreenSheet`, `Platform.copy/pasteboardString/keepScreenOn`, `PlatformImage`); use these instead of iOS-only modifiers in shared views. Live Activities/ActivityKit code is behind `#if canImport(ActivityKit)` (`NowContentState` is the shared state type). Photos go through ImageIO in `ImageTools` (`cgImage(from:maxDimension:)`, `jpeg(fromData:)`); the camera is iPhone only. Settings (`UserDefaults`/`Pref`) don't sync between devices yet.
